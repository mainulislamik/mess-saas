# পরিকল্পনা ও আর্কিটেকচার ব্লুপ্রিন্ট: মেস সেটিংস থেকে মিল রুলস, কাট-অফ সময়সীমা ও গেস্ট মিল কাস্টমাইজেশন

**তারিখ:** ১৪ অক্টোবর, ২০২৬  
**প্রজেক্ট:** ব্যাচেলর মেস ম্যানেজমেন্ট SaaS (`~/mess-saas`)  
**লক্ষ্য:** মেস ম্যানেজারদের হাতে সেটিংস থেকে কাট-অফ সময় (বেলাভেদে), সকালের নাস্তার মিল ইউনিট (০.৫ বা ১.০), এবং গেস্ট মিল অনুমোদন ও সীমা কনফিগার করার পূর্ণ নিয়ন্ত্রণ প্রদান এবং কাট-অফ পার হলে মিল এন্ট্রি লক করা।

## ১. গবেষণালব্ধ বাস্তব মেস প্রেক্ষাপট (Bangladesh Mess Context Research)
বাংলাদেশের ব্যাচেলর মেসগুলোর প্রধান দ্বন্দ্বের জায়গা হলো মিল হিসাব ও কাট-অফ টাইম:
1. **সকালের নাস্তার কাট-অফ:** বাজার বা রান্না সকাল ৭টা-৮টার মধ্যে শুরু হয়, তাই কোনো মেম্বার সকাল ৮টায় ঘুম থেকে উঠে মিল অন/অফ করতে চাইলে খালার রান্না নষ্ট হয় বা কম পড়ে। অধিকাংশ মেসে নিয়ম থাকে: *আগের দিন রাত ১০:০০ বা ১১:০০ টার মধ্যে নাস্তার সিদ্ধান্ত জানাতে হবে।*
2. **সকালের নাস্তার মান (০.৫ বনাম ১.০):** 
   - কিছু মেসে শুধু ডিম-পরোটা বা খিচুড়ি হয়, তারা নাস্তাকে ০.৫ মিল ধরে।
   - অনেক মেসে সকালের নাস্তায় ভারী রান্না বা ভাত খাওয়া হয়, তারা নাস্তাকে পুরো ১.০ মিল হিসেবে গণ্য করে।
   - সুতরাং এটি হার্ডকোড না করে ম্যানেজারকে ০.৫ বা ১.০ সিলেক্ট করতে দিতে হবে।
3. **দুপুর ও রাতের কাট-অফ:**
   - দুপুরের রান্না সকাল ১০টা-১১টায় হয়, তাই সকাল ৯:০০ টার মধ্যে কনফার্ম করতে হয়।
   - রাতের রান্না সন্ধ্যা ৬টা-৭টায় শুরু হয়, তাই বিকাল ৫:০০ টার মধ্যে ফাইনাল করতে হয়।
4. **গেস্ট / মেহমান মিল (Guest Meals):**
   - বন্ধুদের আড্ডা বা আত্মীয় আসলে মেম্বারদের মেহমানের খাবার যোগ করতে হয়। তবে অনিয়ন্ত্রিত মেহমান মিল থাকলে রান্নায় বিশৃঙ্খলা হয়। তাই মেসে গেস্ট মিল চালু থাকবে কি না এবং সর্বোচ্চ কয়টি গেস্ট মিল দিতে পারবে (উদা: সর্বোচ্চ ৩ জন) তা নিয়ন্ত্রণ করা আবশ্যক।

## ২. ডাটাবেজ মডেল ও স্কিমা ডিজাইন (Database Schema Plan)

### ২.১ `messes` টেবিলে `meal_rules` কলাম সংযোজন:
```python
# app/models/mess.py
class Mess(Base):
    ...
    # JSON field with structured defaults
    meal_rules: Mapped[dict] = mapped_column(JSON, default=lambda: {
        "breakfast_unit": 0.5,             # 0.5 or 1.0
        "breakfast_cutoff_time": "22:00",  # "22:00" (রাত ১০:০০ টা)
        "breakfast_cutoff_prev_day": True, # True = আগের দিন রাতে শেষ হবে
        "lunch_cutoff_time": "09:00",      # "09:00" (সেদিন সকাল ৯:০০ টা)
        "dinner_cutoff_time": "17:00",     # "17:00" (সেদিন বিকাল ৫:০০ টা)
        "allow_guest_meals": True,         # গেস্ট মিল অ্যালাউড কি না
        "max_guest_per_meal": 3            # বেলাভেদে সর্বোচ্চ গেস্ট মিল সংখ্যা
    }, nullable=False)
```

### ২.২ `meals` টেবিলে মেহমান / গেস্ট মিল ট্র্যাকিং:
```python
# app/models/meal.py
class Meal(Base):
    ...
    breakfast: Mapped[float] = mapped_column(Float, default=0.0)
    lunch: Mapped[float] = mapped_column(Float, default=1.0)
    dinner: Mapped[float] = mapped_column(Float, default=1.0)
    
    # Guest meals breakdown
    guest_breakfast: Mapped[float] = mapped_column(Float, default=0.0)
    guest_lunch: Mapped[float] = mapped_column(Float, default=0.0)
    guest_dinner: Mapped[float] = mapped_column(Float, default=0.0)
    
    is_off: Mapped[bool] = mapped_column(Boolean, default=False)
    notes: Mapped[Optional[str]] = mapped_column(String(255), nullable=True)

    @property
    def total_meals(self) -> float:
        if self.is_off:
            return 0.0
        return round(
            (self.breakfast + self.guest_breakfast) +
            (self.lunch + self.guest_lunch) +
            (self.dinner + self.guest_dinner),
            2
        )
```

## ৩. ব্যাকএন্ড এপিআই ও কাট-অফ ভ্যালিডেশন লজিক (API & Validation Logic)

### ৩.১ মেস সেটিংস আপডেট এপিআই:
* **রুট:** `PATCH /api/v1/messes/{mess_id}/meal-rules`
* **অনুমোদন:** শুধুমাত্র মেস ওনার (`OWNER`) বা ম্যানেজার (`MANAGER`) এটি পরিবর্তন করতে পারবেন।
* **ইনপুট স্কিমা:**
  ```json
  {
    "breakfast_unit": 0.5,
    "breakfast_cutoff_time": "22:00",
    "breakfast_cutoff_prev_day": true,
    "lunch_cutoff_time": "09:00",
    "dinner_cutoff_time": "17:00",
    "allow_guest_meals": true,
    "max_guest_per_meal": 3
  }
  ```

### ৩.২ কাট-অফ টাইম এনফোর্সমেন্ট ইঞ্জিন (Timezone Aware - Asia/Dhaka):
যখন সাধারণ সদস্য তার মিল সেভ করতে রিকোয়েস্ট পাঠাবে (`POST /api/v1/messes/{mess_id}/meals/me`):
1. **সার্ভার টাইম চেকিং:** সার্ভারের বর্তমান বাংলাদেশ সময় (`now_bd = datetime.now(ZoneInfo("Asia/Dhaka"))`) নির্ধারণ।
2. **অতীত তারিখ গার্ড:** `target_date < today_bd` হলে অবিলম্বে এরর রিটার্ন: *"অতীতের তারিখের মিল পরিবর্তন করা যাবে না।"*
3. **বেলা ভিত্তিক কাট-অফ লজিক:**
   - **সকালের নাস্তা:** 
     - যদি `breakfast_cutoff_prev_day` সক্রিয় থাকে: আজ সকালের নাস্তা গতকাল রাত `breakfast_cutoff_time`-এই বন্ধ হয়ে গেছে। ফলে আজ সকালে কেউ নাস্তা পরিবর্তন করতে চাইলে এরর: *"সকালের নাস্তার সময়সীমা (গতকাল রাত ১০:০০ টা) পার হয়ে গেছে।"*
     - আগামীকালকের নাস্তার জন্য: আজ রাত ১০:০০ টার আগ পর্যন্ত সেট করা যাবে।
   - **দুপুরের খাবার:** 
     - যদি বর্তমান সময় `lunch_cutoff_time` (উদা: ০৯:০০ AM) পার হয়ে থাকে, তবে দুপুরের খাবার লক।
   - **রাতের খাবার:**
     - যদি বর্তমান সময় `dinner_cutoff_time` (উদা: ১৭:০০ / বিকাল ৫:০০ PM) পার হয়ে থাকে, তবে রাতের খাবার লক।
4. **গেস্ট মিল ভ্যালিডেশন:**
   - যদি `allow_guest_meals == False` হয় এবং রিকোয়েস্টে গেস্ট মিল থাকে -> এরর: *"এই মেসে মেহমান মিল অনুমোদন নেই।"*
   - যদি কোনো বেলায় গেস্ট মিল `max_guest_per_meal`-এর বেশি হয় -> এরর: *"প্রতি বেলায় সর্বোচ্চ X টি মেহমান মিল দেওয়া যাবে।"*
5. **ম্যানেজার বাইপাস:**
   - মেস শিট (`/api/v1/messes/{mess_id}/meals/batch`) থেকে ম্যানেজার যখন কোনো সদস্যের মিল এন্ট্রি বা কারেকশন করবেন, তখন এই কাট-অফ বাধা প্রযোজ্য হবে না।

## ৪. ফ্রন্টএন্ড ইউআই ও ইউজার এক্সপেরিয়েন্স প্ল্যান (Frontend UX)

### ৪.১ মেস সেটিংস পেজ (`/dashboard/messes`):
একটি নতুন ডেডিকেটেড সেকশন: **"⚙️ মেস মিল রুলস ও সময়সীমা কনফিগারেশন"**
* **নাস্তার মান সিলেক্টর:**
  - `[ হাফ মিল (0.5) ]` | `[ ফুল মিল (1.0) ]` বাটন/ড্রপডাউন।
* **কাট-অফ টাইম পিকার্স (৩ বেলা):**
  - সকালের নাস্তা: টাইম সিলেক্টর (উদা: `22:00` / রাত ১০:০০) + চেকবক্স: *"আগের দিন রাতে কার্যকর হবে"*.
  - দুপুরের খাবার: টাইম সিলেক্টর (উদা: `09:00` / সকাল ৯:০০).
  - রাতের খাবার: টাইম সিলেক্টর (উদা: `17:00` / বিকাল ৫:০০).
* **গেস্ট মিল কনফিগারেশন:**
  - টগল: `গেস্ট / মেহমান মিল চালু রাখুন [অন / অফ]`
  - ইনপুট: `সর্বোচ্চ গেস্ট সংখ্যা (প্রতি বেলা)` (ডিফল্ট: ৩)
* **বাটন:** "রুলস সেভ করুন" (ম্যানেজারদের জন্য)।

### ৪.২ মেম্বার ড্যাশবোর্ড কার্ড (`MemberDashboardView.tsx`):
* **তারিখ নির্বাচন (আজ বনাম আগামীকাল):**
  - মেম্বাররা যাতে আগামীকালের নাস্তা আজ রাতেই ঠিক করে ঘুমাতে পারে, সেজন্য `[ আজকের মিল ]` এবং `[ আগামীকালের মিল (অগ্রিম এন্ট্রি) ]` ট্যাব থাকবে।
* **রিয়েলটাইম কাট-অফ স্ট্যাটাস ও লক বাটন:**
  - প্রতিটি খাবারের বক্সে স্ট্যাটাস ব্যাজ থাকবে:
    - সময় বাকি থাকলে: `🟢 কাট-অফ: রাত ১০:০০ PM` (বাটন সচল থাকবে)।
    - সময় শেষ হলে: `🔒 সময় শেষ (লকড)` (বাটন ডিসেবল ও গ্রেড আউট থাকবে)।
* **ডাইনামিক নাস্তা বাটন:**
  - সেটিংস অনুযায়ী স্বয়ংক্রিয়ভাবে `চালু (0.5)` অথবা `চালু (1.0)` লেবেল এবং মান ধারণ করবে।
* **গেস্ট মিল কাউন্টার (Guest Stepper):**
  - প্রতি বেলার নিচে যদি গেস্ট মিল অন থাকে, তবে ছোট একটি স্টিপার থাকবে: `মেহমান মিল: [- 0 +]`।
  - মোট হিসাবে দেখাবে: *"আমার মিল: ১.০ + মেহমান: ২.০ = মোট ৩.০ টি মিল"*.

## ৫. বাস্তবায়ন প্রস্তুতি ও ভেরিফিকেশন চেকলিস্ট (Execution Phases)
1. **Phase 1 (Database & Migration):**
   - `models/mess.py`-এ `meal_rules` JSON ফিল্ড যোগ।
   - `models/meal.py`-এ `guest_breakfast`, `guest_lunch`, `guest_dinner` ফিল্ড যোগ।
   - Alembic মাইগ্রেশন তৈরি ও ডাটাবেজে রান।
2. **Phase 2 (Backend Logic & Cutoff Validator):**
   - `api/v1/messes.py`-তে `PATCH /meal-rules` এপিআই তৈরি।
   - `api/v1/meals.py`-তে কাট-অফ ভ্যালিডেশন হেল্পার ও টাইমজোন চেকিং যোগ।
3. **Phase 3 (Frontend Settings UI):**
   - `/dashboard/messes/page.tsx`-এ ম্যানেজারদের জন্য সেটিংস ফর্ম যুক্ত করা।
4. **Phase 4 (Frontend Member Portal UI):**
   - `MemberDashboardView.tsx`-এ কাট-অফ টাইমের উপর ভিত্তি করে বাটন লক/আনলক, আগামীকালের ট্যাব, এবং গেস্ট মিল স্টিপার বাস্তবায়ন।
5. **Phase 5 (E2E Verification):**
   - টাইম সিমুলেশন ও ব্রাউজার টেস্টের মাধ্যমে নিশ্চিত করা যে কাট-অফ পার হলে মিল এন্ট্রি আসলেই লক থাকে।
